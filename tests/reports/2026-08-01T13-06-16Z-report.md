## This run: every finding fixed

Unlike the four runs before it, this one **changed application code**. The nine
defects the earlier runs recorded were fixed at the user's explicit request, and
every test that pinned the old behaviour has been inverted into a regression
test that would fail if the defect returned.

Suite: 1447 passed, **0 skipped** — the three Excel tests that had been skipping
since the first run now execute for real.

| # | Finding | Fix |
|---|---|---|
| 1 | Circuit-breaker constants were uncast `os.getenv` values, so `_register_failure` raised `TypeError`: the breaker could never open, and `test_rdbms_connection` / `test_mongo_connection` raised instead of returning `False` — a wrong DB password produced a 500. | `_int_from_env()` parses both at import, warning and falling back on a non-numeric value. `_FILE_*` duplicates are now plain aliases. |
| 2 | `openpyxl` declared nowhere, so every Excel upload failed with `ModuleNotFoundError` despite XLSX being an advertised type. | Added to `requirements.txt`. |
| 3 | JWT signing key was the committed literal `"super-secret-key"` — anyone with source access could forge a session for any user. | Read from `JWT_SECRET_KEY`; **raises at import when unset**, with the command to generate one. |
| 4 | `authenticate_user` ignored `is_active`, so a deactivated account could still get a token. | Checked after the password comparison (so the response does not reveal *which* failed), and again in `get_current_user` so an already-issued token stops working immediately rather than lasting the hour out. |
| 5 | A non-string `datasource_name` escaped as a raw `AttributeError` that `except ValidationError` does not catch. | Explicit `isinstance` check raising `ValueError`, which Pydantic wraps properly. |
| 6 | `uq_datasource_name_lower` had no `user_id`, so datasource names were unique across **every tenant**. | Replaced with `uq_datasource_user_name_lower`, plus migration `b1f7c2d94a05`. |
| 7 | `create_datasource` ended in `except Exception: print(...); return False`, swallowing the HTTPExceptions raised inside its own `try`. | `except HTTPException: raise` ahead of the catch-all; the catch-all now logs and raises a 500 instead of returning a falsy value. |
| 8 | `search_sort_tables` lowercased the table but not the query, so any uppercase search matched nothing. | Both sides lowercased. |
| 9 | The three `configuration_data` functions returned `None`/`[]` for a datasource the caller did not own — the same value the inactive-table rule returns. | 404 for ownership, a distinct **400 with a readable message** for the inactive-table rule. The routes' now-redundant falsy checks were removed. |

Two further items from the "lower severity" list:

- **`app/models/subscriptions/` deleted.** Unimportable (chained assignment →
  `TypeError`) and a duplicate of the `UserSubscription` already mapped in
  `app/models/user/user.py`. Nothing referenced it.
- **`fetch_rdbms_schema`'s PRAGMA branch** built `PRAGMA table_info([{name}])`
  by f-string with no validation, despite its own comment saying to add some. It
  now runs through `_validated_identifier`, a deliberately looser guard than
  `_IDENTIFIER_RE` — it permits spaces and dots, because real tables are called
  things like "Order Details" and those names come back from the catalog, while
  refusing anything that could close the bracket quoting or start a statement.

### Deployment notes

- **`JWT_SECRET_KEY` is now required.** The application raises at import without
  it. A value has been generated into the local `.env` (gitignored, so each
  environment needs its own) and `tests/conftest.py` sets a fixed test default.
  Documented in TESTING.md.
- **Rebuild the image** to pick up `openpyxl` from `requirements.txt`. The
  running container has it installed manually so this suite could exercise the
  Excel paths.
- **Migration `b1f7c2d94a05` is not applied here** — this dev database has no
  `alembic_version` row, so its schema comes from `Base.metadata.create_all` and
  picks the new index up from the model directly. Environments that do run
  alembic need `alembic upgrade head`. The migration's `downgrade` refuses to run
  with a named error if two users have by then taken the same name, rather than
  failing with an opaque duplicate-key error.
