{# How the query is written: the builder, or a SQL statement typed in full. Both panels are always in the DOM and static/js/tool_configs.js shows one of them, so switching modes keeps whatever was in the other — a switch made by mistake costs nothing. The `required` attribute on the textarea moves with the visible panel: an unfilled hidden `required` field blocks submit with a validation bubble pointing at something the user cannot see. SQL mode is offered only for a relational datasource (`supports_sql`, set by tool_config_service). A CSV or a Mongo collection has no statement to run, so the radio is disabled with the reason rather than accepted and refused on save. This block is re-rendered out of band when the datasource changes — the same swap that resets the query builder, and for the same reason: a query, written or built, belongs to the datasource it was written against. The SQL panel is nested inside the same wrapper rather than sitting beside it because htmx honours hx-swap-oob on top-level response elements only: a sibling would be swapped into the Table field instead. #}
