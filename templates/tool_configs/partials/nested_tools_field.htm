{# Nested Tools — the tools this one embeds, and where their values land. Sits between the query mode and the builder because it belongs to *both* modes: a builder query gets an extra `IN` on a column, a SQL query fills a `:name` placeholder, and which one the row asks for is decided live by static/js/tool_chain.js from the selected mode. Rendered out of band with the mode field and the builder when the datasource changes (see table_field_response.htm): a child must read the same datasource as its parent, so children chosen against the previous one are no longer valid choices and the card starts empty. Only offered for a relational datasource — `supports_sql` is the same flag that enables SQL mode, and a Mongo or CSV datasource has no chain the executor can run. #}

Nested Tools — run another tool or a graph first and restrict this query to what it returns
Each embedded tool runs first, and one column of its result restricts this query — a sub-query, written as two tools. If an embedded tool returns nothing, this tool returns no rows and the ones above it never run. The tools stay usable on their own, and an agent given this tool is given them too.
You can embed a published graph instead of a tool, and one thing about that is worth knowing before you do: a graph containing an Ask a human node will stop and put its question to the person in the conversation, and this tool returns no rows until they answer.
