The mental model

A flow is a conversation on rails. You draw the blocks, connect them, and every visitor walks the same track — the agent says exactly what you wrote, in the order you drew it.

That is the opposite of the AI answering freely, and it is the point. A flow is for the parts of a conversation you want to be the same every time: the greeting, the menu, the qualifying questions, the hand-off. When the rails run out, the AI takes over.

One flow, one agent

A flow is built here on its own, then attached to a single agent from that agent's settings page. It is not owned by the agent — you can build it, park it, and attach it later.

One visitor, one position

Each visitor has a session holding where they are in the flow and the answers collected so far. Nothing else. Close the tab and come back much later and they start again.

The end is a hand-over

Reaching an End block — or simply running out of connections — finishes the flow and lets the agent answer normally from then on. It never loops back to the top.

Draw the happy path first. Start → a greeting → a menu → one branch per option → an End on each. Get that saving, then add the awkward cases. A flow that refuses to save is easier to fix when only one thing changed since it last did.

Making it live: a kind and two switches

This is the single most common reason a flow "does not work". What has to be true depends on what the flow is for, and the three settings are in three different places.

SettingWhereWhat it means
Kind Here, on the Flow Builder list Agent — a chatbot's own conversation, attachable to one agent. Generic — a child flow, never attached to an agent, run by another flow's Run Flow block. Chosen when you create a flow and switchable afterwards.
Active Here, on the Flow Builder list The flow is published. A draft is editable but never runs for a visitor — and a draft generic flow is not offered to a Run Flow block either. One rule for both kinds.
Attached The agent's own settings page This agent runs this flow. Only Active agent flows that are not already attached elsewhere can be picked — a generic flow never appears in that dropdown at all.
A generic flow needs no agent. It goes live the moment it is Active and a Run Flow block in some other flow points at it. If a flow is attached to an agent you cannot make it generic — detach it on the agent's page first, which stops that agent's conversation deliberately rather than as a side effect.

Two consequences worth knowing:

  • Save is not publish. Editing an attached, active flow changes what visitors get as soon as you press Save. There is no separate publish step and no draft copy — the Unsaved changes badge on the canvas is telling you the opposite thing, that your edits are not live yet.
  • Turning an attached flow back to draft leaves it attached and simply stops the agent running it. That is the safe way to take a flow out of service without unpicking the agent's settings.
Nobody is mid-conversation when you save. Visitors already in the flow are walking the graph you just replaced. If you have moved things around, expect a few sessions to land somewhere odd and sign off early — they will, rather than crash, but a busy agent is better edited quietly.

Variables, honestly

Several blocks can store what a visitor said into a named variable — email, issue_type, whatever you call it. The session carries those names and values for the rest of the conversation.

Where a stored variable can actually be read:

PlaceReads variables?
If / Else conditionYes — this is what it is for
Send Email — recipientsYes — a TO may be {{EMAIL}}
Send Email — template variablesYes — bind each one to a collected value
Send Message textYes — Thanks {{NAME}}!
Ask for Input promptYes
Menu / Dropdown promptYes
End Flow closing messageYes
Menu / Dropdown option labelsNo — see below
Names must match exactly. {{email}} and {{EMAIL}} are two different variables here, because every block treats them that way — an If / Else compares the name as you typed it. A name this conversation has no value for is left on screen as you wrote it rather than blanked: a visible {{ORDR_REF}} tells you which name is misspelled, where an empty gap would just look like a value that failed to arrive.
Option labels are the exception, on purpose. A Menu option's label is not only what the visitor reads — it is also stored as their answer, and it is the question an AI Fallback after it gets asked. Substituting into it would quietly change three things at once, so labels are left exactly as typed. Put the variable in the prompt above the buttons instead.

A value can come from anywhere that stores one: an Ask for Input answer, a Menu choice, an AI Fallback's answer, a Run Graph row count, or a value a Run Flow block brought back from another flow.

Ports and connections

Every block has zero or more ways out. A block with one shows a small dot on its bottom edge; a block with a choice to make shows a labelled pill for each — written and failed under a Create File block, one per option under a Menu. A connection runs from a dot or a pill to the top of another block.

Pills sit side by side under the block and wrap onto a second line only when they run out of room, so a Menu of two options reads as one choice rather than a stack. A label longer than its pill is shortened with an ellipsis — hover the pill to read the whole of it.

Green means the block did its work; red means it could not. A block that can fail — Create File, Download File, Run Graph, Run Flow, Send Email — shows a green pill for the way out it takes when it worked and a red failed pill beside it, and the connector leaving the red pill is red and dashed. End Flow is red as well, because that is where the conversation stops. A Menu's options and If / Else's True and False stay grey: those are choices, not outcomes — nothing has gone wrong when a visitor presses the second button.

The canvas arranges itself top to bottom as you build, so a block you add lands where its connections put it. Drag a block if you want it somewhere else — the canvas then leaves your arrangement alone until you press Tidy up, which hands the arranging back. A connector's × and its two end handles appear when you hover it.

  • One connection per way out. A dot or pill already joined to something cannot be joined to a second block; the save is refused rather than one of the two being picked silently.
  • A way out left unconnected is an ending. The conversation signs off there. That is legitimate — you do not need an End block on every branch — but it means a forgotten connection looks exactly like a deliberate ending, and the visitor gets "Thank you for chatting with us. Goodbye!" in the middle of your flow.
  • Menu and Dropdown grow a pill per option. Add a fourth option and a fourth pill appears, labelled with what you typed; delete an option and its connection goes with it.
  • Two pills mean two outcomes. If / Else has True and False; Run Graph and Send Email have a success pill and a failed pill. Leave failed unconnected and a failure quietly ends the conversation — connect it to a Send Message if you would rather say something.
  • A Goto's jump is a dashed line. It is drawn from the Goto block round to the block it names, so a flow that loops back to its own menu looks like one. It has no × and no handles: change where it goes by editing the Goto block.
Nothing may connect back into Start, and nothing may leave an End. Both are refused on save. To restart a conversation, end it — the next message begins a new one.

Start · Send Message · End Flow

The three that just talk. Start takes no settings — it marks the entry point, and a flow must have exactly one.

Send Message has one field, the message text, and does not wait for a reply — it says its piece and moves to the next block in the same turn. Chain three of them and the visitor gets three bubbles at once.

End Flow takes an optional closing message and finishes the conversation. Leave it blank and the visitor gets "Thank you for chatting with us. Goodbye!"

A blank Send Message is skipped, not sent. It hops onward rather than drawing an empty chat bubble — so a message you meant to write and did not is invisible rather than ugly. If there is nowhere left to hop, it becomes the end of the conversation.

Ask for Input

Asks a question and waits. Whatever the visitor types next is stored under the variable name you give, and the flow continues from the single output port.

Prompt textThe question. Shown as a normal message
Store answer in variableA short name — email, order_number
Anything they type is accepted. There is no format checking here — asking for an email address and being given "no" stores the word "no". If the answer has to be usable, follow it with an If / Else on contains and ask again on the False branch.

Menu / Buttons · Dropdown

Both offer a fixed set of choices and wait. The difference is only how the widget draws them: Menu renders buttons, which suits three or four options; Dropdown renders a select, which suits a longer list.

Prompt textThe question above the choices
OptionsOne row each. Each grows its own output port
Store choice in variableOptional. Records which one they picked

Every option needs somewhere to go. An option whose port is left unconnected ends the conversation the moment somebody picks it — which is a perfectly good "no thanks, goodbye" option and a very confusing accident.

If / Else

Looks at one stored variable and leaves by True or False. Three tests, and no others:

OperatorTrue when
not_emptyThe variable holds anything at all. The compare value is ignored
equalsThe variable is exactly the compare value
containsThe compare value appears somewhere inside it
A variable that was never set is empty, not an error. An If / Else on a name nothing stored takes the False branch every time — which is usually what you want, and is worth remembering when a branch never fires: check the spelling of the variable name against the block that stores it.

Goto

Jumps to a named block. It has nothing to connect — the jump is its way out, and the canvas draws it as a dashed line running round to the block it names. Use it to reuse one ending, or one "can I help with anything else?" section, from several branches without drawing the same blocks three times.

A Goto that jumps backwards can loop. The engine stops a runaway at 25 hops within a single turn and signs off, so a loop cannot hang the conversation — but it does end it, and the visitor sees a goodbye they did not ask for. A loop is fine as long as something in it waits for the visitor.

AI Fallback

Hands this one turn to the language model, then carries on down the flow. Use it where a scripted answer will not do — an open "what is your question?" step in the middle of an otherwise fixed path.

GuardrailsWhat it must not do — topics to refuse, tone to keep
Prompt / instructionsWhat it should do at this point in the conversation. Also what it searches the knowledge base for when the visitor arrived by clicking a button
Answer using Attached datasource — query the agent's data · Knowledge base — the documents on this block · Prompt only — no lookups
Language modelIn-built LLM, or Attached LLM API
Attached API keyRequired when the mode is Attached LLM API
Store the answer in variableOptional. Keeps the answer for later blocks to use

Choosing Knowledge base gives this block its own document store: upload files or paste text on the block, then Train. Until it is trained it has nothing to answer from. The knowledge base belongs to the block, not the flow, so two AI Fallback blocks can answer from two different sets of documents.

Wired off a Menu? Write the prompt as the question. A button click carries no typed words, so this block is asked about the option's label — and a label is written to be clicked, not to be searched for. An option labelled "Email me the data" pointed at a project proposal finds that document's privacy section and answers that it cannot share user data: from the knowledge base, and about the wrong subject. On a click, the block searches for the Prompt / instructions as well as the label, so putting the real question there ("give a detailed summary of the proposal in plain language") is what fixes it. Typed questions are searched for on their own.
Name a variable to email the answer. The visitor is shown the answer either way; naming a variable also keeps it — the whole answer, bullet points and table rows included — so a Send Email block further down can bind to it and mail the visitor what the AI found, and an If / Else can branch on whether it managed to answer at all. This block ends the turn, so an Email block after it sends on the visitor's next message; the variable is still there by then.

Run Graph

Runs one of your Pipelines in the middle of the conversation and waits for it to finish. Two ports: done and failed.

GraphWhich pipeline. Only published ones are listed
Store the number of results inA variable holding how many rows came back
The count is what you branch on. Follow it with an If / Else on that variable — equals 0 for "we found nothing", anything else for a result — so the visitor gets a sensible sentence either way. And connect failed: a pipeline that errors otherwise ends the conversation without explanation.

Run Flow

Runs another one of your flows as a single step of this one, then carries on. Values go in, the other flow runs as normally as if it were attached to an agent itself — it can ask questions, show menus, hand a turn to the AI — and the values you name come back. Two ports: done and failed.

This is how you stop drawing the same thing twice. Build "collect the customer's details" once, then call it from three places.

Flow to runYour published generic flows, never the flow you are editing. An agent flow is not offered — that is a chatbot's own conversation, not a step
Values passed inOne row per variable that flow reads. From a value this conversation collected, an agent variable, or a fixed value
Values brought backOne row per variable that flow stores. Give each one the name to keep it under here; leave it blank not to bring it back

Both lists are read off the flow you pick, so they always match what it actually does. A value it reads from somewhere this page cannot see — a Run Graph block inside it is handed everything — can be added by hand with Add a value.

The called flow gets its own variables. It starts with exactly what you passed in and nothing else, and when it finishes only the values you named come back. Its internal variable names are its own business — two Run Flow blocks calling the same flow cannot tread on each other, and renaming a variable inside it breaks nothing here except a row you can re-point.
An End Flow block inside a called flow means "return". It does not end the conversation — the caller picks up from the block after this one. If that End Flow block has a closing message it is still said, and the caller carries on from the visitor's next message; if it is blank, nothing is said and the caller carries straight on. A flow that simply runs out of blocks returns the same way.

A flow cannot run itself, and a loop back to a flow already running takes failed rather than going round again. Five calls deep is the limit. Connect failed: a flow that has since been deleted, unpublished, or switched to an agent flow otherwise ends the conversation without explanation.
Nothing to pick? The list is your published generic flows, and a brand-new flow is an agent flow unless you said otherwise. On the Flow Builder list, press Make Generic on the flow you want to reuse and make sure it is Active — then it appears here.

Send Email

Queues an email and says nothing to the visitor — it hops straight on, so put a Send Message after it if somebody should be told. Two ports: queued and failed.

TemplateFrom Emails → Templates. Required
Send throughAn SMTP server from Emails → Servers. Required
To / Cc / BccAt least one TO. May be a fixed address or a {{VARIABLE}}
VariablesOne binding per placeholder the template declares
Store the email's id inOptional. Useful for looking the message up later

Each template variable is bound to one of three sources:

  • A value the conversation collected — anything an Ask for Input, a Menu, an AI Fallback or a Run Graph block stored under a variable name
  • An agent variable — the standing values on the agent, such as {{COMPANY}}
  • A fixed value — the same text every time
queued does not mean delivered. The failed port fires for something knowable right now — a template that has been deleted, a binding that resolves to nothing. Whether the mail is later accepted by the relay is answered by the delivery log under Emails → Messages, not by this block.

Create File · Download File

A pair. Create File writes rows to a file; Download File hands that file to the visitor. They are two blocks rather than one because the file has to exist before it can be offered — and because plenty of flows want the first without the second, writing a file and mailing the link instead.

Neither block says anything on its own. That is the same rule Send Email keeps: a block that announced "I have made your file" would be putting words in your mouth. Write the sentence yourself with a Send Message block. The one exception is the button below, which you have to switch on.

Create File
Where the rows come fromA Run Graph block's result, an AI Fallback block's answer table, or a variable holding a dataset
File formatCSV, Excel (XLSX), Text or Parquet
File nameThe extension is added for you. {{VARIABLE}} works, so invoice-{{ORDER_REF}} gives a file per visitor
Store the file path inOptional. A path, not a link — useful in a log line or an email to your own team

What each source gives you:

  • A Run Graph block — every row the pipeline returned, re-read when the file is written. The conversation only ever saw the first twenty; the file holds the lot
  • An AI Fallback block — the table in its answer, when the answer had one. Real columns, not the pipe-separated text the variable holds
  • A variable — rows stored as JSON become columns. Anything else is text, and only Text can write text: there is no honest way to turn an AI answer's prose into a spreadsheet
Download File
File to hand overThe Create File block that writes it. Required — it names the block, so you can put other blocks in between
Store the download link inOptional, and the whole point when there is no button: {{FILE_URL}} in a Send Message block, or bound into an Email block
Show a download buttonOff by default. On, the visitor sees a button under whatever the flow just said
Button text · colourOnly when the button is on. The text takes {{VARIABLE}} too
The link belongs to one conversation and lasts a day. It carries the widget's id and that visitor's session, and it works for nobody else — pasting it into another browser gives "that file could not be found". After a day it says it has expired, which is a different sentence on purpose.
Connect failed. A block whose data holds no rows, a variable the conversation never set, a Create File block a branch skipped — all of them take that port, and with nothing drawn there the conversation signs off instead. A file block never carries on as though it had worked.

Pipelines 7 · Look something up

"Check whether we have their order, then say so."

What to draw
Ask for Input → Run Graph ─┬─ done   → If / Else ─┬─ True  → Send Message ("Found it…")
                           │                     └─ False → Send Message ("Nothing under that number")

When a save is refused

The whole flow is checked on every Save, so a refusal can name a block you were not editing. Nothing is stored when it is refused — your drawing is still on screen, unchanged.

MessageWhat to do
Flow must contain at least one nodeAn empty canvas cannot be saved. Add a Start block
Flow must contain exactly one Start nodeYou have none, or two. Delete the spare
Every node must have a unique, non-empty idUsually a copy-paste that went wrong — delete the duplicate block and redraw it
Start node cannot have incoming edgesSomething connects back into Start. To repeat a section, Goto the block after Start
End node cannot have outgoing edgesAn End is final. Delete the connection leaving it
Edge references an unknown nodeA connection to a block that no longer exists. Delete and redraw it
Node '…' has more than one edge on the same output ('…')Two connections leave one port. Delete one — to fan out, add a Menu or an If / Else
If/Else node is missing a variable nameFill in which variable to test
If/Else node has an invalid operatorPick one of the three from the list
Goto node must target a valid nodeIts target was deleted or never chosen. Pick one
Menu node must have at least one optionA menu with nothing to pick cannot be answered. Add an option
Dropdown node must have at least one optionThe same
AI Fallback is set to use an attached LLM API but no key is selectedChoose a key, or switch back to the in-built model
Email node is missing an email templatePick one under Emails → Templates first

What a visitor's session holds

Two things, and it is worth knowing how little that is:

  • Where they are — the one block they are waiting at
  • What they have said — a flat list of variable names and text values

Every value is text. A count from Run Graph is the text "0", not the number zero — which is why If / Else compares it as text and why equals 0 is written exactly like that.

There is no history of the path taken, no undo, and no way to reach a value from a block that did not store one. If you will need something later, store it when it is offered — a Menu's Store choice in variable costs nothing and cannot be recovered afterwards.
